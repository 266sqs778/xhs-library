# 精华小书 · 书稿格式规范

> 一份书稿同时是两样东西：**TXT 是可读的纯文本**，**PDF 是同一份稿子的渲染升级**。
> 不在 TXT 里塞样式代码，只用行首 `@@` 标记内容身份；换渲染器、换开本、换主题，稿子不用重写。

## 一、三条不可让渡的原则

1. **身份优先于美观**。任何一段文字，读者必须一眼看出它是「原文照录」「他人评论」还是「编者文字」。三者样式永不混用。
2. **照录不改字**。原文与评论只在标记内加行内重点，不润色、不缩写、不改标点、**不补写句末标点**。允许的归一化只有三项：略去平台表情代码与字体不支持的表情符号、合并换行、统一引号样式；三者必须在章节说明里逐项写明。原帖评论常以表情代码或无标点收尾，照录就照录到那里为止。
3. **提炼必须可追溯**。核心观点、拆解、按语都是编者归纳，必须与原话分栏呈现，且不得新增原文没有的事实。

## 二、内容身份与板块对照

| 内容身份 | 书稿写法 | TXT 里 | PDF 里 |
|---|---|---|---|
| 章 | `第X章 标题` | 普通一行 | 居中大标题 + 目录书签 |
| 节内小标题 | `@@H2 文字` | 普通一行 | 黑体左对齐，上下留白 |
| **核心观点（一句话）** | `@@LEAD 文字` | 普通一行 | 浅米色卡片 + 朱红左色条 + 「核 心 观 点」标签 |
| 重点句 / 金句 | `@@KEY 文字` | 普通一行 | 朱红黑体、左缩进、加大行距 |
| 分点拆解 | `@@POINT 文字` | 普通一行 | 悬挂缩进的圆点列表 |
| 编者按语 / 说明 | `@@NOTE 文字` | 普通一行 | 灰色小字 + 自动「编者注｜」前缀 |
| 评论署名 | `@@BY 昵称｜赞数 · 身份` | 普通一行 | 灰色小字、前缀破折号，紧贴引用 |
| 评论 / 引文照录 | `@@QUOTE 文字` | 普通一行 | 浅灰底引用块 + 灰色左色条 |
| **精髓评论特写** | `@@GEM 文字` | 普通一行 | 独立特写卡：大字楷体、朱红细框、居中标签「本册精选 · 精髓评论」、上下留白 |
| 插图 | `@@IMG 路径 \| 图注` | 普通一行 | 等比居中 + 居中小字图注，图与图注不拆页 |
| **图里的文字** | `@@PIC 文字`（用 `／` 表示图内换行） | 普通一行 | 浅米底细框卡片 + 「图 版 文 字 · 照 录」标签，按图片原断行 |
| 独立图注 / 说明 | `@@CAP 文字` | 普通一行 | 灰色小字居中 |
| 段落分隔 | `@@RULE` | 一行标记 | 细横线 + 上下留白 |
| 强制分页 | `@@PAGE` | 一行标记 | 分页 |
| 普通正文 | 直接写 | 普通一行 | 宋体两端对齐、首行缩进 |

行内标记（可嵌在任意一行里）：`**重点**` → 朱红黑体加粗；`==重点==` → 淡黄底色高亮。
TXT 里看得见标记字符，PDF 里只留视觉效果；照录段落用这两个标记标重点，不算改字。

## 三、组合规则（最容易做乱的部分）

**评论区的固定三件套**：`@@BY` → `@@QUOTE` → `@@NOTE`。
署名必须写清三件事：**谁说的**（昵称）、**分量**（赞数 / 回复数）、**关系**（作者本人回复 / 回复谁 / 同一串回复）。没有署名的引用不许入书。

**精髓评论怎么抬**：全书只抬 1–2 条为 `@@GEM`，其余一律 `@@QUOTE`。入选标准三选一即可，但必须在紧随的 `@@NOTE` 里说清理由：
- 把原文的框架推进了一步（不是复述）；
- 对原文提出了有效校正；
- 一句话照见了读者自己的处境。
`@@GEM` 前同样必须有 `@@BY`。不要把高赞自动等同于精髓。

**核心观点怎么提炼**：
- 每章开头一条 `@@LEAD`，只写**一句**、不超过 60 字，是该章的结论而非内容提要。
- 章内用 `@@POINT` 分点拆解，每点一层，不叠床架屋。
- 原文里支撑结论的关键句用 `==…==` 高亮，最锋利的半句用 `**…**`。
- 提炼写成编者归纳，不冒充作者原话；拿不准是不是原话，就用 `@@QUOTE` 照录，别改写。

**图片里也有内容**：图文笔记的配图常常本身就是文字卡。三条规定：
- 图里能读出来的字，一律用 `@@PIC` 逐字转录，`／` 处按图片原断行；装饰性元素（引号、下划线、水印、色块）不转录，但要在紧随的 `@@NOTE` 里说明「哪些没算文字」。
- 图片本身要不要放进书里，看它是不是内容：标题卡、图表、时间线 → 收；推广截图、带第三方水印的付费长图 → 不收，也不转录，只在数据章写明「几张、为何不收」。
- 转录必须说明来源：是原帖配图，还是某条评论的附图（写清谁的回复、图片尺寸），二者不能混。

**视觉层级**：`@@GEM` > `@@LEAD` > `@@KEY` > `@@PIC` > `@@QUOTE` > `@@NOTE` > 正文。
一页里最多出现一个高阶板块，否则「重点」就不再是重点。

## 四、一整套流程（SOP）

| 步 | 做什么 | 产出 |
|---|---|---|
| 1 采集 | 拿到正文全文、配图、发布时间、互动数、可见评论及回复关系 | 结构化 JSON + 图片文件 |
| 2 建档 | 给每条内容记：来源、作者、是否照录、可见范围（首屏 / 全量） | 采集说明 |
| 3 精选 | 按「延伸 / 校正 / 照见处境」筛评论，写未选入理由；剔除广告与同义重复 | 入选清单 |
| 4 提炼 | 每章一句 `@@LEAD`；拆 `@@POINT`；标 `==…==` 与 `**…**` | 观点骨架 |
| 5 成稿 | 按身份套标记，写成纯 TXT；保留署名与原链接 | `book_source.txt` |
| 6 排版 | `--preset xhs`（小红书风格）或 `--preset modern` 出书（当代内容绝不能用古典模板） | PDF |
| 7 验收 | 目录书签、插图、残留标记、引文逐字比对、行首标点、版权文案 | 校验报告 + 抽样页 |

## 五、硬规则

- 排当代非公版内容**必须** `--preset xhs` 或 `modern`；默认 `classic` 会写「原书著作权已入公有领域」，这是错误声明。
- 版式选择：`xhs` = 白底珊瑚红、黑体正文、字号 10.4/行距 17.6、版心更宽，适合信息流摘录；`modern` = 宣纸底宋体、传统书籍观感。两者都走同一份 TXT 稿，换 preset 不用改稿。
- 只拿到首屏评论时，必须写明「非全量、非热度排序」，不许包装成热评榜。
- 评论区上传图片若来源/授权不明（推广截图等），不收录，并在出处说明里交代。
- 摘录含他人原创图文，默认仅供个人存档；公开传播需授权，书里按此口径标注。
- 引用段落里出现 `**` `==` 之外的一切改写都算事故；只允许上文列明的三项归一化，且必须声明。新增句号、补写标点同样算事故。
- 图注、`@@IMG` 路径、`@@BY` 里的文字不要含 `<` `>` `&`。

## 六、验收清单

- [ ] 每条 `@@QUOTE` / `@@GEM` 前面都有 `@@BY`，署名含昵称、分量、关系
- [ ] `@@GEM` 全书不超过 2 条，且后面有 `@@NOTE` 说明理由
- [ ] 每章一条 `@@LEAD`，且是结论不是提要
- [ ] 引文与采集到的原文逐字比对通过（去掉换行后比对）
- [ ] PDF 里搜不到 `@@`、`**`、`==` 等残留标记
- [ ] 目录书签数与章数一致，页码正确
- [ ] 插图完整居中、图注清晰；缺失时显示「〔插图缺失〕」而不是静默丢图
- [ ] 全书无行首中文标点、无方框乱码、无「公版 / 国学经典」残留
- [ ] 出版说明与封底的版权表述与内容年代一致
